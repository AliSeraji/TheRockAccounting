# design-sync notes

## Repo shape

- This is a React Router 7 **app** (`private: true`, no `exports`/`main`/`module`), not a published design-system package. There is no library `dist/`; the converter runs in synth-entry mode, bundling components straight from `app/components/` (`cfg.srcDir`). `.d.ts` prop contracts are therefore extracted from source and weaker than a library build would give.
- Scope chosen by the user on the first sync: **all components under `app/components/`** (~116), with authored previews. Many page-level components (invoice, receipts, customers, warehouse, settings) read Zustand stores (`~/store/*`) and react-router, so expect provider setup or floor cards for those.
- Path alias `~/*` -> `./app/*` comes from `tsconfig.json`. **Do not set `cfg.tsconfig`.** The converter's tsconfig-paths plugin (`lib/bundle.mjs`, `tsconfigPathsPlugin`) tries the bare path before `/index.tsx`, so a directory import like `import InvoiceBody from '~/components/invoice'` (in `receipt_issue/sections/InvoiceSection.tsx`) resolves to the directory itself and esbuild fails with `Cannot read file "app/components/invoice": Incorrect function`. Without `cfg.tsconfig`, esbuild's built-in tsconfig resolution handles `~/` correctly for every file under `app/` (verified by probing esbuild directly). `bundle.mjs` must not be forked, so config is the fix.
- The synth entry needs `--entry ./dist/index.js` (a path that doesn't exist). The walk-up from it finds the repo's `package.json`, so `PKG_DIR` is the repo root, and the soft dist lookup fails over to synthesizing from `cfg.srcDir`. Without `--entry`, the converter looks for `node_modules/rock-fact/` and crashes.
- **`.design-sync/default-exports.ts` (via `cfg.extraEntries`) is required.** The synth entry is `export * from "<file>"` per source file, which (1) skips every default export (79 component files use `export default`) and (2) silently drops any named export defined in two files (`AdditionalNote` in both `receipts/delivery/` and `receipts/sales/`). The first validate failed `[BUNDLE_EXPORT]` with 70/209 components missing from `window.RockFact`. The module re-exports them by name. **When a new default-exported component is added to the app, add a line there** or it won't be on the bundle.
- Colliding names get folder-qualified exports: `AppHeader`, `InvoiceTableRow`, `RequestLowerTable{Body,Header,Row}`, `RequestUpperTable{Body,Header,Row}`, `SettingsInvoiceSection`, `ReceiptIssueInvoiceSection`, `WarehouseTableFooter`, `DeliveryAdditionalNote`, `SalesAdditionalNote`. The bare `Header`/`Body`/`Row`/`InvoiceSection`/`AdditionalNote` are excluded with `componentSrcMap: null`, and each qualified name is pinned to its source file.
- The converter matches components to source files by file name, and names like `Table.tsx`, `TableHeader.tsx`, `InfoBox.tsx`, `Signature.tsx` repeat across `ui/`, `invoice/`, `warehouse/`, `customers/` and `receipts/*`. The shadcn table parts are pinned to `ui/table.tsx`, and `InfoBox`/`Note`/`ReceiptHeader`/`Signature` to `receipts/delivery/`.
- shadcn `ui/` files use lowercase kebab names (`button.tsx`, `alert-dialog.tsx`); the converter's src-path fuzzy match expects PascalCase, so `componentSrcMap` pins may be needed.

## Build

- Package manager: yarn 1.22.22 (`yarn install --frozen-lockfile`). Node v26.3.0 at first sync; no `.nvmrc`.
- **Prop contracts come from `.design-sync/gen-types.mjs`.** With no library build there's no `.d.ts` tree, so on the first sync every emitted `<Name>.d.ts` was an `[key: string]: unknown` stub (`[DTS] parsed 0 .d.ts files`) and the design agent had no API to code against. The script runs `tsc --noEmit false --declaration --emitDeclarationOnly` into the gitignored `.design-sync/.cache/types/`, copies in `default-exports.ts` (tsconfig's `**/*` skips dot-folders), and writes an `index.d.ts` barrel mirroring the synthesized JS entry. `package.json` `publishConfig.types` points the converter at that barrel; `publishConfig` has no effect on a private app. Output is emitted inside a dot-folder so the app's own `tsconfig.json` never picks it up. Result: stubs dropped from 217 to 36. **Run it after `yarn build` and before the converter** (it's in `buildCmd`); if it's skipped, every contract silently reverts to a stub.
- `app/app.css` is Tailwind v4 **source** (`@import 'tailwindcss'`, `@theme`, `@apply`) and cannot be shipped raw. `cfg.cssEntry` points at the app build's compiled stylesheet instead: run `yarn build` first.
- **Fonts come from `cfg.extraFonts`, not `cssEntry`.** Vite's compiled CSS references fonts by root-absolute URL (`url(/assets/Samim-<hash>.woff2)`), which the converter can't map back to `build/client/assets/`. The first build shipped `fonts/fonts.css` with six `@font-face` rules pointing at `/assets/…` and no font files at all. The source stylesheets use relative URLs and ship correctly: `samim-font/dist/font-face.css` (Samim 400/500/700) and `@fontsource-variable/vazirmatn/index.css` (Vazirmatn Variable, arabic/latin/latin-ext subsets).
- **Inter was removed from the theme (user decision, first sync).** `--font-sans` in `app/app.css` named `'Inter'` first, but the app never loaded Inter, so validate flagged `[FONT_MISSING] "Inter"`. The user chose to remove it from the theme rather than ship Inter or accept the warning, so `--font-sans` now starts at `ui-sans-serif`. Samim is the app's body font.
- `react-router build` prints "Error when using sourcemap for reporting an error" for `ui/field.tsx`, `ui/separator.tsx`, `ui/switch.tsx`. These are warnings; the build succeeds.
- npm's allow-scripts policy skips esbuild's postinstall in `.ds-sync/`; esbuild still works via its platform optional dependency (verified 0.28.2).
- Staging scripts with `cd` in a Bash call moves the shared working directory for later PowerShell calls. Use absolute paths (e.g. `yarn --cwd <repo> build`).
- **Never leave a shell's working directory inside `ds-bundle/`.** On Windows, the next `package-build.mjs` fails with `EPERM, Permission denied` when it tries to delete `ds-bundle/` while a shell still sits in it (hit twice on the first sync). Inspect bundle files with absolute paths; if EPERM appears, move the shell back to the repo root and rerun.
- **No lib forks.** In `lib/source-kit.mjs`, derivation from source runs only when the component list is empty, and any non-null `componentSrcMap` pin makes it non-empty. Before `gen-types.mjs` existed, adding 22 pins dropped the list from 209 components to exactly those 22. A fork fixing this was written and then removed: once the types barrel provides a real export list, discovery comes from the barrel and pins add on top as documented. **If `componentSrcMap` pins ever collapse the component count, check that `gen-types.mjs` ran** (build log: `[DTS] parsed N .d.ts files`, not 0).
- **`dtsPropsFor` covers four shadcn wrappers** whose props all come from another component (`ComponentProps<typeof Label | Input | Separator | Button>`): `FieldLabel`, `SidebarInput`, `SidebarSeparator`, `SidebarTrigger`. The extractor keeps only props declared in this package, so these came out as stubs. The bodies follow the converter's emitted style for the wrapped component. `SidebarInput` deliberately has no `children` (void `<input>`; a string child crashes the render). The other 32 stub contracts are genuinely prop-less components (store-driven sections like `CustomerForm`, `SettingsSidebar`, `InvoiceSummary`) and are correct.
- `[EXPORT_COLLISION]` for all 79 names in `default-exports.ts` is an artifact of synth-entry mode: `package-build.mjs` adds every component to the exported set, so each re-export looks like a duplicate. Previews import from `rock-fact`, which carries the merged exports.

## Previews

- Format: `export const Name = () => (...)` per story. Shared sample data goes **above** the first export, because `.prompt.md` examples are cut from one `export const` to the next.
- The app sets no document direction (`<html lang="en">`); RTL is applied per container (`dir="rtl"`). Every Persian preview wraps its content in `dir="rtl"`, as the app does.
- Overrides: `Table` uses `cardMode: column` (wide); `Dialog` uses `cardMode: single` with viewport `720x520` so the overlay renders inside the card.

## Known render warns

- **Destructive buttons render dark text on red.** The theme defines `--destructive` but not `--destructive-foreground`, so Tailwind never generates `text-destructive-foreground` and the text inherits the default color. The app has the same contrast problem; previews are faithful to it. This is the "1 missing token" in validate's token line.

## Upload

- First sync (2026-09-17): `DesignSync` had no design-system authorization and `/design-login` can't run in the non-interactive VS Code session. The user must run `claude` in a terminal at the repo root and type `/design-login` there. The local build and verification proceeded; no project was created yet, so no `projectId` is pinned.

## Re-sync risks

- **`cfg.cssEntry` is a content-hashed filename** (`root-<hash>.css`). Any change to styles or components changes the hash; after `yarn build`, update `cssEntry` to the new `build/client/assets/root-*.css` or the converter will ship a stale or missing stylesheet.
- The compiled CSS contains only the Tailwind utilities the app currently uses. Classes the design agent writes that the app never used will not resolve.
- `build/client/assets/PersianDatePicker-*.css` (date picker styles) is a separate chunk not covered by `cssEntry`.
